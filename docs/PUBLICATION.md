# Перед первой публикацией

Здесь то, что делает владелец своими руками и что **после `git push`
исправить нельзя**. Всё остальное в этом репозитории обратимо; этот файл —
про необратимое.

Порядок важен: сначала ворота, потом сжатие истории, потом push. Сжать
историю после публикации невозможно — объекты остаются доступны по хэшу
и живут в форках и кэшах.

---

## Пять условий, и снятое одно не снимает остальных

Их ведёт `release-gate`, здесь они названы для человека.

| № | условие | чем снимается |
|---|---|---|
| 1 | что публикуем: карта эндпоинтов | решение 10 — **снято** |
| 2 | под каким именем и с каким первым экраном | решение 11 — **снято** |
| 3 | живая приёмка пройдена | `docs/ACCEPTANCE.md`, пункты 0–8 с 7а и 7б — **вами, после публикации (решение 34)** |
| 4 | README и лицензия на месте | решение 13 — **снято** |
| 5 | в дереве нет литералов машины, история сжата | решение 19 — **вами** |

Смешивать их — ошибка, которую легко сделать: снято большинство, а не
главное. «Решения приняты, можно публиковать» — неверный вывод. О готовности
контура говорит только условие 3.

---

## Шаг 1. Проверить, что в дереве нет следов вашей машины

```
python -m pytest tests/ -q
```

Среди тестов есть те, что смотрят **всё дерево**, а не только изменённое:
имя пользователя, пути вида `Users/…`, буква диска, путь внутрь виртуального
окружения, следы прежней раскладки. Хук этого не заменяет — он видит только
файлы, попавшие в индекс, и литерал в нетронутом файле пропустит навсегда.

Отдельно проверьте, что закрыто всё, что закрывать положено:

```
git check-ignore storage_state.json daemon_token daemon_port chrome_profile recordings fingerprint.json endpoints.local.json memory/STATE.md
```

Попадание обязано быть **по каждому имени**. Отсутствие хотя бы одного —
не замечание, а остановка: это единственная защита от необратимого.

---

## Шаг 2. Решить про идентичность коммита

Сжатие создаёт один коммит, и его автор — то, что увидит любой читатель
навсегда. Выбор ваш, и он делается **один раз**:

* **имя и личная почта** — как во всех нынешних коммитах;
* **имя и служебный адрес хостинга** — почта не публикуется; хэндл всё равно
  виден на аккаунте.

Учтите: ваше настоящее имя уже публикуется лицензией и файлом уведомлений —
это решение 13, и его никто не отменял. Скрывать в истории то, что открыто
в `NOTICE`, смысла нет; речь только о почтовом адресе.

Проверить, что стоит сейчас:

```
git config user.name
git config user.email
```

---

## Шаг 3. Сохранить полную историю локально

**Сделайте это до сжатия.** Ветка остаётся у вас и никогда не пушится:

```
git branch история-до-сжатия
```

Проверьте, что она есть, прежде чем идти дальше:

```
git log --oneline история-до-сжатия | wc -l
```

Число должно совпадать с числом коммитов, которые вы видите в `git log`.

---

## Шаг 4. Сжать

```
git checkout --orphan публикация
git add -A
git commit
```

`git add -A` здесь — единственное разрешённое исключение из правила
«коммит конкретными путями» (`CLAUDE.md`): у orphan-ветки индекс пуст,
и добавить в него нужно ровно то, что было в прежнем индексе. Условие
исключения — перед `git checkout --orphan` команда
`git status --porcelain --untracked-files=all` печатает пустоту, а после
`git add -A` число строк `git ls-files` совпадает с числом до сжатия.
Не совпало — остановитесь: в коммит уходит что-то сверх прежнего индекса.

`--orphan` создаёт ветку без родителей: у неё не будет истории вовсе, а не
«переписанная история». Это ровно то, что нужно — прежние ревизии не должны
существовать в публичном репозитории даже недостижимыми.

Сообщение коммита пишите как первый абзац README, а не как отчёт: читатель
увидит его в списке. За хронологией отсылайте к `docs/DECISIONS.md` —
там записи с датами, и она подробнее любой
истории коммитов.

Затем сделайте эту ветку основной:

```
git branch -M публикация main
```

**Проверьте перед push:**

```
git log --oneline
```

Ровно один коммит. Если их больше — остановитесь и разберитесь; после
публикации это уже не чинится.

---

## Шаг 5. Что уходит вместе с кодом

Прежде чем нажать push, посмотрите глазами на то, что публикуется:

```
git ls-files
```

Убедитесь, что в списке нет ничего, чего вы там не ждёте. Это последняя
проверка, которую делает человек, а не программа, — и единственная, которая
ловит то, о чём никто не подумал заранее.

Приватное в список попадать не должно вовсе: рабочее состояние, планы,
промты, аудит, живая сессия подписки. Всё это закрыто `.gitignore`, и шаг 1
это подтвердил, — но посмотреть стоит.

---

## Шаг 6. Push

Первый push необратим. С этого момента история, идентичность автора и всё
содержимое существуют у форков и в кэшах поисковиков, даже если вы удалите
репозиторий через минуту.

`git push` закрыт для всех агентов в настройках проекта. Это не формальность:
публикация — решение владельца, и принимается оно один раз. Оно принято
07.09.2026 (решение 34): запрет снимается на один шаг — сам push — и
возвращается следующим же коммитом.

---

## Чего эта процедура не решает

**Отношения с «Гарантом».** Лицензия описывает права на **наш код** и ничего
не говорит о том, допустимо ли автоматизированное обращение к чужому сервису
с точки зрения его правил. Это открытый вопрос, он решается не лицензией
и не этим файлом. Разбор — `docs/DECISIONS.md`, решение 13.

**Отпечаток вашей подписки.** Из карты эндпоинтов он убран (решение 16),
и каждый ставящий получает свой. Но подписка, на которой всё проверялось,
одна — ваша, и риск для неё публикацией не снимается.

**Первое впечатление.** Оно не отыгрывается. Если условие 3 не снято,
установку за вас проверит первый читатель, и узнаете вы об этом из его отзыва.
