# `hooks/` — защита от необратимой утечки

Здесь один файл: `pre-commit`. Он смотрит на то, что уходит в индекс, и
отклоняет коммит, если внутри оказался секрет или путь конкретной машины.

Файл написан под **POSIX `sh`, а не под bash**: на Debian и Ubuntu
`/bin/sh` — это dash, и bash-овские расширения там не работают вовсе.
Правя хук, держитесь POSIX. Одна такая конструкция уже стоила дорого:
чтение списка файлов через `read -d ''` под dash не выполняло тело цикла
НИ РАЗУ — хук выходил с кодом 0 и пропускал всё, а на Windows, где `sh`
это bash, видно этого не было (найдено первым прогоном CI, 08.09.2026).

## Включить в свежем клоне — руками, один раз

```
git config core.hooksPath hooks
```

Это **ручной шаг**, и обойтись без него нельзя: `core.hooksPath` живёт
в `.git/config`, а `.git/config` не клонируется. При клоне приедет файл
`hooks/pre-commit`, но не его включение — то есть защита у вас выключена,
и git об этом не скажет. Пока команда выше не выполнена, хук не работает.

Проверить, что включено:

```
git config --get core.hooksPath
```

Ответ `hooks` — значит, работает.

## Что именно он проверяет

**Содержимое индекса, а не имена файлов.** Проверка по имени бесполезна:
имя меняется одной командой, а `.gitignore` не останавливает `git add -f`.
Поэтому для каждого файла, уходящего в коммит, читается его содержимое
из индекса (`git show :файл`) и ищутся:

* структура `storage_state` (ключи `cookies` и `origins` вместе) — живая
  сессия подписки;
* заголовок `Set-Cookie`;
* длинная base64url-строка в файле, который не является кодом, — так
  выглядит `daemon_token`. Кодом считаются `.py`, `.ps1`, `.md`, `.sh`,
  `.yml`, `.toml`, `.ini`, `.cfg` и подобное; **`.txt` кодом не считается**
  и проверяется — туда секрет и попадает чаще всего;
* домашний каталог в форме пути и имя пользователя этой машины;
* путь внутрь `.venv`, буква диска в тексте;
* файл, закрытый `.gitignore` и добавленный через `git add -f`;
* образцы из `.git/garant-secrets`, если этот файл у вас есть (ниже).

Точные образцы выписаны в самом `pre-commit`, и там единственное место, где
их правят. Второй список разошёлся бы с первым молча.

**Исключённых файлов нет ни одного.** Каждое правило применяется ко всему,
что уходит в индекс, включая сам `pre-commit`. Раньше три файла из `scripts/`
были освобождены поимённо; вместе с этими файлами (решение 18) удалены и
освобождения, и сам механизм — пустой фильтр в защите выглядит работающим,
а строку в него дописывают молча. Условие, при котором «исключений нет»
остаётся выполнимым, одно: **образец пишется так, чтобы не находить сам
себя** — через класс символов, а не голым литералом. Иначе хук отвергнет
собственную правку, и его снова придётся освобождать.

Имя пользователя хук **спрашивает у машины** (`$USER`, `$USERNAME`,
`id -un`, имя каталога `$HOME`), а не хранит литералом: публичный файл,
называющий чью-то учётную запись, — это ровно та утечка, от которой хук
и защищает. Если ни одного имени получить не удалось, хук печатает об этом
строку в stderr и правило не применяет. Молчаливо пропущенная проверка хуже
отсутствующей, поэтому строка обязательна — если вы её видите, знайте: эта
проверка сейчас выключена.

## `.git/garant-secrets` — необязательный файл, и его отсутствие норма

Бывают литералы, которые ловить надо, но которые нельзя держать в дереве:
имя чужого хранилища, каталог прежней раскладки на чьей-то машине. Написав
их в детектор, вы превращаете публичный файл в носитель того, что он
запрещает.

Поэтому они выносятся в `.git/garant-secrets`:

* формат — одно расширенное регулярное выражение (`grep -E`) в строке;
* пустые строки и строки, начинающиеся с `#`, игнорируются;
* файл лежит в `.git`, значит не индексируется и не клонируется;
* негодный для `grep -E` образец пропускается с сообщением в stderr,
  а не молча.

Пример (образцы **выдуманные**, ни одного настоящего здесь нет):

```
# следы прежней раскладки на моей машине
(^|[^A-Za-z0-9])07_Черновики[\/]
Проект-Ромашка
```

**Файла у вас нет — и это правильно.** В нём лежат следы ЧУЖОЙ машины,
которых у вас не может быть, и искать их в вашем коде нечего. Ничего
создавать не нужно; заведите его, только если у вас появились свои
литералы, которые не должны уехать в публичный репозиторий.

## Осознанный обход

```
SKIP_GARANT_HOOK=1 git commit …
```

Хук выходит сразу, напечатав строку в stderr. **Следа этот обход не
оставляет**: в коммите его не видно, в истории тоже — только в вашей
консоли в момент коммита. Значит, отвечает за него тот, кто набрал команду,
и восстановить постфактум, что проверка была пропущена, нельзя.
